00 · RESEARCHWhat we learned before redesigning

The founder's feedback on v0.1: Contrail (dark) didn't land. The light Home Journal and Pilot Profile were the closest. The ask: Apple's iOS 26 Liquid Glass look, light-first, white + blue, with Flighty, "Flightdeck" and Strava as references.

SourceKey takeawaysHow Flyby uses it
Liquid Glass
developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass
WWDC25 “Meet Liquid Glass” (219), “Build a SwiftUI app with the new design” (323)		 Liquid Glass is a dynamic material that bends and blurs what's behind it. It forms a separate functional layer for navigation and controls that floats above content. Tab bars float, and can minimize on scroll (.tabBarMinimizeBehavior(.onScrollDown)). Small glass elements flip light/dark based on what's behind them. Two variants: Regular (adaptive, the default) and Clear (needs a dimming layer over bright media). Use tint sparingly, only for primary actions; color belongs in the content layer. Avoid custom backgrounds on bars and avoid overusing glass on custom controls. Group custom glass in GlassEffectContainer. Buttons: .buttonStyle(.glass) / .glassProminent. Glass only on the nav/control layer: tab bar, floating map controls, the stats panel floating over the map, filter chips. Content cards stay solid white for legibility. Blue tint is reserved for Record and primary buttons. Standard TabView, so we get system glass for free.
HIG · Tab bars
developer.apple.com/design/human-interface-guidelines/tab-bars		 "Use a tab bar to support navigation, not to provide actions." Keep labels short (one word), use SF Symbols (filled preferred), and keep tab tint distinct from bright content. Tension: Record is an action. We keep the founder's 5 tabs, but Record is a real tab whose selection is intercepted to present the Log sheet, and the previous tab stays selected (see §05).

Why Skyglass

  • It matches what the founder responded to: the light Journal and Profile screens. Their layouts carry over and gain glass navigation.
  • It's native to iOS 26. Standard TabView, toolbars, sheets and glass button styles give us real Liquid Glass (refraction, adaptive light/dark flipping, scroll-edge effects) with little custom code. It will age with the platform rather than against it.
  • Content stays the hero. Glass is limited to the navigation/control layer, following Apple's guidance, so flights, maps and photos supply the color, and text sits on solid white wherever it's dense.
  • Dark Mode is still first-class: every token has a dark value, and glass adapts automatically (see the dark Home mockup).

05 · NAVIGATIONFive tabs on a floating glass bar, with Record at the center

Set at the founder kickoff and matching MVP-PLAN.md D2: Home · Explore · Record · Flights · Profile. Built on the standard iOS 26 TabView, so the bar is real Liquid Glass, floats above content, and minimizes on scroll.

TabSF SymbolPurposeA11y id
Homehouse.fillBefore social: your journal (year summary + recent flights). After social: a Following ⇄ You segmented control.tab.home
Exploreglobe.americas.fillAirports you've visited or want to visit, and airport pages. For discovery, not flight planning.tab.explore

Rationale & rules

  • With five tabs, Record is the true center and the only tinted item, which follows Apple's guidance to reserve tint for the primary action.
  • HIG note: tab bars are meant for navigation, not actions. Record is implemented as a regular Tab whose selection is intercepted (the selection binding reverts) to present the Log a Flight sheet. The previous tab stays selected, so the bar never shows an empty Record screen.
  • .tabBarMinimizeBehavior(.onScrollDown) on Home, Flights and Explore lets content (maps, flights) breathe; the bar returns when you scroll up.
  • Home is for highlights, Flights is the archive. Home shows the year and the latest flights; "All flights" opens the Flights tab. Achievements live in Profile.
  • Labels are always shown. At accessibility sizes, the system's large-content viewer shows the label on long-press.
  • No navigation-style UI anywhere: no moving map, no ownship, no ETA or guidance. Flyby is a journal.

Privacy on shared maps

  • Sprint 1: trimming runs on-device in TrackPrivacy.trim(_:distance:) before any recap is rendered. Later, a Supabase function stores a separate shared geometry, so Followers and Public only ever receive the trimmed track (RLS on tracks). Very short tracks that can't be trimmed hide both endpoints and show a note.
  • The privacy-zone center is offset by a random amount fixed per pilot (not per flight), so repeated shares can't be averaged to find the field.
  • Applies to cards, detail views seen by others, recaps, and Explore airport pages (home airport never lists the pilot as "based here").

Map style · "Activity map" (Strava-inspired, Flyby-owned)

Strava's activity maps work because the basemap is quiet and the route is loud: a muted, low-contrast base (hillshade, faint contours, de-emphasized roads and labels), one thick saturated line with round joins and a slight shadow, and clear start/finish dots. Flyby keeps that hierarchy but uses its own palette: a Flyby Blue route with a white casing (not orange), a white start dot with a blue ring, and a navy end dot. Feed cards are map-heavy, with stats above an edge-to-edge map, and logbook rows get compact thumbnails.

extension Color {
    enum Flyby {
        static let bg       = Color("bg")        // #F5F8FC / #0A0F1A
        static let surface  = Color("surface")   // #FFFFFF / #141B28
        static let surface2 = Color("surface2")  // #EEF3F9 / #1C2536
        static let label    = Color("label")     // #0B1220 / #F2F5FA
        static let label2   = Color("label2")    // #4A5568 / #A3AEC2
        static let primary  = Color("primary")   // #0A63DB / #4DA3FF  "Flyby Blue"
        static let gold     = Color("gold")      // #F2A93B achievements only (text on light: #9A5B00)
        static let route    = Color("route")     // #0A63DB / #4DA3FF, drawn over a white casing (see Map style)
        static let altitudeRamp = Gradient(colors: [Color("altLow"), Color("altMid"), Color("altHigh")])

        /// Maps altitude (ft MSL) onto the ramp for track segments and the profile chart.
        static func altitude(_ ft: Double, ceiling: Double = 18_000) -> Color {
            let t = min(max(ft / ceiling, 0), 1)
            return t < 0.5
                ? Color("altLow").mix(with: Color("altMid"), by: t * 2)
                : Color("altMid").mix(with: Color("altHigh"), by: (t - 0.5) * 2)
        }
    }
}

10 · PRINCIPLESAccessibility, privacy & scope guardrails

Accessibility

  • WCAG AA for all text in both modes (see the table in §02). Non-text elements (route, toggles) are at least 3:1.
  • Dynamic Type up to AX5, with stat grids that reflow. Charts provide an Audio Graph (AXChartDescriptor) and a VoiceOver summary ("Climbed to 11,500 ft in 18 minutes…").
  • Maps: VoiceOver reads "Route from San Carlos to Lake Tahoe, 135 nautical miles."
  • Supports Reduce Motion, Reduce Transparency (materials become solid surfaces), and Increase Contrast variants for every token.

Privacy & scope

  • Every flight is Private by default (both the DB default and the UI default). Followers and Public are explicit choices, and every card shows which one applies.
  • The home airport is hidden and the track trimmed on every non-owner view and every recap image.
  • A journal, not a navigation tool: no live position, no guidance, no planning features. A small "Not for navigation" line appears on the detail screen and on recaps.
  • This document is a provisional local draft. Scope and naming may change.
